2. CAUSA-RAIZ (fonte primária: código do builder da Vercel)
===============================================================================
`@vercel/node` NÃO faz bundle por padrão. Ele traça o grafo com `@vercel/nft` e transpila
cada `.ts` individualmente, renomeando para `.js` e preservando os specifiers de import:

  vercel/vercel packages/node/src/build.ts
    function renameTStoJS(path) { if (path.endsWith('.ts')) return path.slice(0,-3) + '.js'; ... }
    if (tsCompiled.has(path)) { preparedFiles[renameTStoJS(path)] = entry; }
    // Compile ES Modules into CommonJS
    ... if (pkg.type === 'module' && path.endsWith('.js')) { // already ESM, do not transpile
    const enableBundling = process.env.VERCEL_API_FUNCTION_BUNDLING === '1' && ...

  vercel/vercel packages/node/src/typescript.ts
    rewriteRelativeImportExtensions: true   // reescreve .ts -> .js; NÃO adiciona extensão

Como o `package.json` tem `"type": "module"`, o output permanece ESM e vale a regra do loader
ESM do Node: import relativo EXIGE extensão (nodejs.org/api/esm.html#mandatory-file-extensions).
O import `'../../server/ai/http'` era copiado literalmente para `api/ai/status.js`, e em runtime
o Node procurava `/var/task/server/ai/http` (sem extensão) → ERR_MODULE_NOT_FOUND → 500.

O tracer NÃO perde os arquivos: `@vercel/nft` tem retry dedicado `.js` → `.ts`
(node-file-trace.js, linhas 208-209 do pacote instalado):
    if (this.ts && dep.endsWith('.js') && e1 instanceof NotFoundError) {
      const depTS = dep.slice(0, -3) + '.ts';
      resolved = await this.resolve(depTS, path, this, cjsResolve);
    }
